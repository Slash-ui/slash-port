What is on port 3000?

EADDRINUSE tells you a port is taken. It does not tell you what took it, which project it belongs to, or whether killing it is a good idea. slash-port answers all three, then kills it for you - after a confirmation that names it.

$ npm install -g slash-port

Beginner mode is the default: every row says what the thing is, where to open it, and whether closing it is a good idea. Press m for pids, command lines and uptime. Press x and it asks before it signals anything - the protected row is refused outright, because there is no confirmation that lets you kill sshd.

Three things a port number cannot tell you

Every other answer to “what is on 3000” gives you a pid. A pid and the word node is not an answer.

What it actually is

Frameworks are matched before the runtimes that host them, so node …/vite reports Vite dev server, not Node.js. Around ninety signatures, from Next.js and Django to Postgres and docker-proxy - and when none of them fit, it says so rather than repeating the process name back at you.

Which project it belongs to

The directory above node_modules in the command line - or, with --docker, the compose project Docker names it by. Two Vite servers on 5173 and 5174 stop being interchangeable, and so do two Postgres containers on 5432 and 54322 - which is exactly the moment you need to tell them apart.

Whether killing it is wise

Some things are never worth killing from a list. Those rows are labelled and refused before a dialog is ever offered, rather than being made easy to get wrong.

The safety rules are fixed, not configurable

Killing the wrong process at a terminal is easy, and unrecoverable. So there is no flag, no config file, and no combination of arguments that gets round any of these.

  • Nothing is killed without a confirmation that names it. Not in the interactive list, and not from a script - --kill requires both --port and --yes.
  • Some processes are refused outright. The init process, sshd - killing it locks you out of a remote machine - macOS and Windows session processes, slash-port itself, and the shell that launched it.
  • SIGTERM before SIGKILL. A process that ignores SIGTERM is reported as having survived. Escalating is a second, deliberate keystroke - never automatic.
  • A process that has already exited is never signalled, because by then its pid may belong to something else entirely.
  • No network access, at any point. By default it reads the local socket table and the local process table, and asks nothing else on the machine anything either. --docker is the one exception, off until you ask for it, and what it reads is a socket on this machine. No telemetry, no update check, no config file.

The kill key is deliberately not next to a navigation key, and colour never carries meaning on its own - a protected row is labelled [protected] and one owned by somebody else is labelled [locked], as well as coloured, so NO_COLOR loses you nothing.

Reference

Node 22 or newer, on Linux, macOS, and Windows. Piped output is plain text with no control codes, so it survives a grep. 

# the interactive list
slash-port

# open on one port
slash-port 3000

# a pattern, where x is any digit, or a range with both ends included
slash-port 3xxx
slash-port 3000:3005

# for a pipe, a script, or another program
slash-port --plain
slash-port --json

# kill from a script: named, and confirmed
slash-port --kill --port 3000 --yes

# a pattern can match several ports, so killing with one takes --all
slash-port --kill --port 3000:3005 --yes --all

Keys

↑ ↓ j k Move. PgUp PgDn page, g G jump to the ends
/ Filter on anything in the row, or on ports with 3xxx and 3000:3005. Enter keeps it, Esc clears it
x Kill the selected port - opens the confirmation
y f n In the confirmation: SIGTERM, force with SIGKILL, cancel
r u q Rescan, toggle UDP, quit

How each platform reads the socket table

Platform Method
Linux /proc/net/tcp directly, with socket inodes mapped through /proc/[pid]/fd. No lsof, which many container images do not have, and no subprocess at all
macOS lsof in field-output mode, which emits one tagged field per line and does not shift when a value gets wider, plus ps for full command lines
Windows netstat -ano and tasklist, which exist on every edition and avoid PowerShell's startup cost

On Linux, descriptors belonging to other users are not readable without privileges. Those rows show no owner rather than failing the scan, and the list says so - run with sudo to resolve them.
